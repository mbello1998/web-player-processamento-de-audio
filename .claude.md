# DropHunter Studio - Configurações, Diretrizes & Guia Técnico do Agente (.claude.md)

Este documento define as diretrizes arquiteturais, padrões de código, fluxos de compilação e regras mandatórias para qualquer agente ou desenvolvedor que atue no **DropHunter Studio**.

---

## 📌 1. Visão Geral do Projeto
O **DropHunter Studio** é uma estação web avançada de discotecagem, streaming e processamento de sinal em tempo real (DSP).
- **Core DSP**: Web Audio API com cadeia profissional de masterização, simulador de Stems (Zero-Bleed Crossover), equalizador ISO de 10 bandas e compressor dinâmico anti-pumping.
- **Inteligência de Mixagem**: Algoritmo Drop Hunter para detecção em tempo real de build-ups, drops e silêncios, permitindo cortes automáticos com BPM Sync e beatmatching harmônico.
- **Catálogo Híbrido**: Reprodução e streaming de YouTube, SoundCloud e bibliotecas locais.
- **Design & UI**: Interface inspirada no Spotify Desktop com temas neon dinâmicos, paleta adaptativa extraída da capa do álbum, transições de desmontagem/remontagem de grade e animações suaves via GSAP e Web Animations API.

---

## 🛠️ 2. Comandos Essenciais de Desenvolvimento & Build

### Iniciar Servidor Local
```bash
python server.py
```
- Inicia o backend Flask em `http://localhost:5050`.
- Interface principal do player: `http://localhost:5050/player.html`.
- Fornece endpoints de busca, extração e streaming de áudio (`/api/audio/stream`, `/api/audio/info`, `/api/search`, etc.).

### Compilar e Empacotar o Player
```bash
python build_full_player.py
```
> [!IMPORTANT]
> **OBRIGATÓRIO**: Sempre execute este comando após realizar alterações em `player_template.html`, `assets/css/player.css` ou `assets/js/player.js`. Ele compila a versão final otimizada em `player.html`.

### Validação de Sintaxe JavaScript
```bash
node --check assets/js/player.js
```
Execute sempre antes de realizar commits para garantir que não há erros de sintaxe no core do player.

## 🎛️ 4. Arquitetura do Motor de Áudio Web Audio API (DSP)

A cadeia de sinal foi projetada para qualidade de estúdio, impedindo distorções harmônicas e oscilações bruscas de volume (*pumping/breathing*):

```
[ <audio> Element ]
       │ (createMediaElementSource)
       ▼
[ Stems DJ Filter ] ───────► (Crossover Zero-Bleed: Vocais, Bateria, Baixo, Outros)
       │
       ▼
[ Equalizador ISO 10 Bandas ] (31Hz, 62Hz, 125Hz, 250Hz, 500Hz, 1kHz, 2kHz, 4kHz, 8kHz, 16kHz)
       │
       ▼
[ AnalyserNode ] ──────────► (FFT 2048: VU Meter, Espectrograma e Detecção Drop Hunter)
       │
       ▼
[ Master Gain Node ] ──────► (Controle de Volume estilo VLC até 200%)
       │
       ▼
[ Compressor Master ] ─────► (Threshold: -1.5 dBFS, Ratio: 3.5:1, Attack: 10ms, Release: 250ms, Knee: 12dB)
       │
       ▼
[ Safety Soft Clipper ] ───► (WaveShaper com curva tanh e threshold em 0.98 - retenção limpa de picos)
       │
       ▼
[ AudioDestinationNode ] ──► (Alto-falantes / Saída de Áudio)
```

### Regras Críticas de Áudio & Drop Hunter:
1. **Janela de Proteção Anti-Corte (`isBufferingOrSeeking`)**: Durante seeks, scrub na barra de tempo ou após retroceder faixas, a detecção de silêncio e troca de música do Drop Hunter deve ser suspensa por no mínimo 3.5 segundos (`lastSeekTimestamp`).
2. **Comportamento do Botão Anterior (`manualTransition('prev')`)**: Se a faixa atual já tocou por mais de 3 segundos, o primeiro clique deve apenas reiniciar a faixa para o tempo `0:00`. Um segundo clique rápido (< 2.0s) salta para a faixa anterior na fila.
3. **Resiliência a Restrições de Idade (+18)**:
   - Se o YouTube rejeitar o áudio por exigência de login (+18), o backend memoriza o erro em cache negativo por 10 minutos para evitar chamadas contínuas.
   - O player usa `skipUnplayableTrack` para pular a faixa indisponível de forma graciosa sem travar a playlist.
   - Para reproduzir faixas restritas, o usuário deve exportar seus cookies em formato Netscape para `cookies.txt` na raiz.

## 🎨 5. Diretrizes de Interface (UI) e Estilo

1. **Sem Emojis Soltos no Código**: Nunca insira caracteres emoji Unicode brutos no HTML ou JS para botões e ações. Utilize ícones vetoriais SVG através da função `window.uiIcon(...)` ou classes `.ui-icon`.
2. **Transições de Navegação**:
   - As trocas entre abas da barra lateral (Início, Navegar, Biblioteca, etc.) devem utilizar desvanecimento bidirecional suave (`fadeIn`/`fadeOut`) em nível de página combinado com desmontagem e remontagem em cascata dos cards (`.spotify-card`).
   - Evitar bloqueios rígidos por `prefers-reduced-motion` que impeçam animações visuais quando solicitadas pelo usuário.
3. **Cache Busting de Assets**: Sempre que editar `assets/js/player.js` ou `assets/css/player.css`, incremente a versão de cache na tag de inclusão em `player_template.html` (`?v=YYYYMMDD_XX`).
